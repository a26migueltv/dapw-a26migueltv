## Exercicio 1: Reprodución de contorno de desenvolvemento con Composer

### 1.1 Conexión á máquina devmtv2

Con `F1` → *Remote-SSH: Add New SSH Host* engadiuse a segunda máquina de desenvolvemento co comando:

```bash
ssh dadmin@192.168.56.102
```

Despois, con `F1` → *Remote-SSH: Connect to Host* conectouse á IP `192.168.56.102` co contrasinal do usuario `dadmin` e abriuse un novo terminal.

**Captura 1 – Visual Studio Code conectado a devmtv2**

![image-20261009101623495](/home/sanclemente.local/a26migueltv/.config/Typora/typora-user-images/image-20261009101623495.png)

### 1.2 Clonado do repositorio e instalación das dependencias

Como `devmtv2` é unha máquina nova, primeiro instaláronse PHP e Composer e configurouse Git:

```bash
sudo apt update
sudo apt install -y php-cli php-zip unzip composer
git config --global user.name "Miguel Tubío Vidal"
git config --global user.email "a26migueltv@iessanclemente.net"
git config --global credential.helper store
```

Clonouse o repositorio `mtvt0201_1` e abriuse en Visual Studio Code:

```bash
git clone https://gitlab.com/a26migueltv-grupo/mtvt0201_1.git
cd mtvt0201_1
ls -a
```

O directorio `vendor` non existe, xa que está incluído no `.gitignore` e non se subiu ao repositorio.

**Captura 2 – Estado inicial do proxecto sen o directorio vendor**

![image-20261009102105722](/home/sanclemente.local/a26migueltv/.config/Typora/typora-user-images/image-20261009102105722.png)

Instaláronse tódolos paquetes que necesita o proxecto a partir de `composer.json` e `composer.lock`:

```bash
composer install
```

**Captura 3 – Contido do directorio vendor co paquete fakerphp/faker instalado**

![image-20261009102156491](/home/sanclemente.local/a26migueltv/.config/Typora/typora-user-images/image-20261009102156491.png)

### 1.3 Fixar a versión concreta dos paquetes

Eliminouse o directorio `vendor` para borrar tódalas librerías instaladas:

```bash
rm -rf vendor
```

No `composer.json` substituíuse a restrición `^1.24` pola versión concreta instalada (`1.24.1`), para que sempre se instale exactamente a mesma versión:

```json
"require": {
    "fakerphp/faker": "1.24.1"
}
```

**Captura 4 – composer.json con versión concreta de fakerphp/faker**

![image-20261009102304700](/home/sanclemente.local/a26migueltv/.config/Typora/typora-user-images/image-20261009102304700.png)

Instaláronse de novo os paquetes:

```bash
composer install
```

Composer avisa de que `composer.json` e `composer.lock` non están sincronizados. Para sincronizalos habería que executar `composer update`.

Comprobouse que todo funciona executando o script:

```bash
php xerar_alumnos.php
```

**Captura 5 – Contido do ficheiro alumnos.csv**

![image-20261009102442612](/home/sanclemente.local/a26migueltv/.config/Typora/typora-user-images/image-20261009102442612.png)

### 1.4 Instalación dun paquete de desenvolvemento nunha versión concreta

En [getcomposer.org](https://getcomposer.org/) → *Browse Packages* buscouse o paquete `friendsofphp/php-cs-fixer` e instalouse a penúltima versión só para o contorno de desenvolvemento, coa opción `--dev`:

```bash
composer require --dev friendsofphp/php-cs-fixer:X.Y.Z
```

**Captura 6 – Instalación de php-cs-fixer en modo desenvolvemento**

![Captura 6 - Instalación de php-cs-fixer](img/ex1_cap06.png)

O paquete aparece na sección `require-dev` do `composer.json`.

**Captura 7 – composer.json co paquete php-cs-fixer en modo desenvolvemento**

![Captura 7 - composer.json con require-dev](img/ex1_cap07.png)

Subíronse os cambios ao repositorio:

```bash
git add .
git commit -m "Fixa versións e engade php-cs-fixer en desenvolvemento"
git push
```

## Exercicio 2: Reprodución de contorno de desenvolvemento con NPM

### 2.1 Clonado do repositorio e instalación das dependencias

Instalouse Node.js e npm en `devmtv2`:

```bash
sudo apt install -y nodejs npm
```

Clonouse o repositorio `mtvt0201_2` e abriuse en Visual Studio Code:

```bash
git clone https://gitlab.com/a26migueltv-grupo/mtvt0201_2.git
cd mtvt0201_2
ls -a
```

O directorio `node_modules` non existe, xa que está incluído no `.gitignore`.

**Captura 1 – Estado inicial do proxecto sen o directorio node_modules**

![Captura 1 - Proxecto sen node_modules](img/ex2_cap01.png)

Instaláronse tódolos paquetes que necesita o proxecto:

```bash
npm install
```

**Captura 2 – Contido do directorio node_modules co paquete axios instalado**

![Captura 2 - Directorio node_modules](img/ex2_cap02.png)

### 2.2 Fixar a versión concreta dos paquetes

Eliminouse o directorio `node_modules`:

```bash
rm -rf node_modules
```

No `package.json` substituíuse a restrición `^1.20.0` pola versión concreta instalada (`1.20.0`):

```json
"dependencies": {
    "axios": "1.20.0"
}
```

**Captura 3 – Contido do package.json coa versión concreta de axios**

![Captura 3 - package.json con versión concreta](img/ex2_cap03.png)

Instaláronse de novo os paquetes e comprobouse que todo funciona:

```bash
npm install
node index.js
```

**Captura 4 – Execución de index.js**

![Captura 4 - Execución de index.js](img/ex2_cap04.png)

### 2.3 Instalación dun paquete de desenvolvemento nunha versión concreta

En [npmjs.com](https://www.npmjs.com/) buscouse o paquete `eslint` e, na lapela *Versions*, escolleuse a penúltima versión. Instalouse en modo desenvolvemento (`--save-dev`) e coa versión exacta (`--save-exact`), para que no `package.json` non se engada o símbolo `^`:

```bash
npm install --save-dev --save-exact eslint@X.Y.Z
```

![Captura 5 - Instalación de eslint](img/ex2_cap05.png)

**Captura 6 – Contido do package.json con versión concreta de ESLint en modo desenvolvemento**

![Captura 6 - package.json con devDependencies](img/ex2_cap06.png)

Subíronse os cambios ao repositorio:

```bash
git add .
git commit -m "Fixa versión de axios e engade eslint en desenvolvemento"
git push
```
